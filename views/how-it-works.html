Design choices

  • Speaker = source. Mic is ME, tab is THEM. No diarization model needed, and labels are never wrong (unless your speakers bleed into the mic, so wear headphones).
  • Key stays server-side. The browser asks this app for a 10-minute OpenAI key scoped to one transcription session, then streams audio straight to OpenAI. The real OpenAI and Anthropic keys never reach the page.
  • Context is per call. The context box (who, goals, facts not to overstate) goes into every coach, strategy and recap call. Presets fill it; each saved session keeps the context it ran with. It never goes into a shared recap.
  • Recap on Stop. One Claude pass over the numbered transcript: summary, what went well, misses linked to their line, next step, follow-up email draft, CRM notes.
  • Sharing. “Share recap” makes a link with a random id and an 8-character code, shown once. Send them separately. 5 wrong codes lock the recap for 15 minutes; it expires after 14 days; Revoke deletes it at once.
  • Server VAD cuts turns at pauses, so lines end on sentence boundaries instead of every 5s. Mic gets a lower threshold (0.3) because it's quieter than tab audio.
  • One coach call in flight. New lines during a call mark it dirty; it re-runs once when done. Never queues a backlog.
  • Structured output. Claude returns a fixed JSON schema, so the UI can't break on a chatty reply.
  • Fails soft. Dropped transcription sockets reconnect on their own (1s, 2s, 4s… max 10s) while audio keeps flowing. A failed coach call keeps the last advice on screen and retries. Mic, tab-share and API key problems show a plain-English fix in the sidebar.

What I'd build next

  • Stream the coach response so the “Now” line lands in ~1s.
  • Prompt-cache the context block; only the transcript tail changes.
  • CRM write-back for the recap's notes and next step.
  • Meeting bot mode (join Zoom/Meet as a participant) for the other side's audio without tab sharing.
  • Team mode: playbooks per deal stage, scorecards across reps.
